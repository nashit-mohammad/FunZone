# Technical analysis

## Repository evidence

- `.github/workflows/daily-game.yml` creates the unique handoff directory and exports its path as `DAILY_GAME_HANDOFF_DIR`, but the generated prompt only references the environment variable and never includes its concrete value.
- `.github/copilot/prompts/daily-game.md` directs the agent to follow `RTK.md` and use the workflow-provided handoff directory.
- `RTK.md` says to always prefix shell commands with `rtk` and has no CI fallback.
- The user-provided run log confirms GitHub-hosted Ubuntu lacks `rtk`; Copilot's `rtk printenv ...` command failed, it could not discover the env path, and it stopped before reading the initialized handoff. The PR action then correctly reported operation `none` because no application files changed.

## Requirements mapping

| Acceptance criterion | Technical requirement | Validation approach |
|---|---|---|
| Give Copilot the concrete handoff location | Append the current `$work_dir` to the per-run prompt before Copilot starts | Static review of prompt-generation block |
| Preserve schedule, handoff and PR behavior | Leave preparation/upload/PR controls intact except for prompt context | Static diff review |
| Do not add dependencies or broaden permissions | Clarify RTK's CI fallback instead of installing RTK; leave permissions unchanged | Static review |
| Record validation limitations | Document static checks and that only a future GitHub run can prove PR creation | Handoff artifacts |

## Proposed design

Keep the current workflow and task prompt. After copying the static prompt and adding open PR metadata, append a short trusted run-context section containing the exact `$work_dir`, and instruct Copilot to use that path directly rather than resolving the environment variable. Update `RTK.md` so it requires the `rtk` prefix when available, but explicitly permits direct commands or built-in file tools on hosted runners where RTK is absent. This lets the agent continue without adding/installing RTK and without changing workflow permissions.

## Implementation tasks

1. Add the concrete handoff directory to the run-specific prompt created by the workflow.
2. Add an explicit no-RTK fallback to `RTK.md`.
3. Record the implementation and a static test plan/report; do not dispatch the workflow.

## Data, interfaces, and dependencies

- No new dependencies, secrets, permissions, or interfaces.
- `$work_dir` is generated by the workflow from the current time and GitHub run ID, then inserted as plain prompt context.

## Risks, assumptions, and open questions

- The Copilot CLI's editor/file tools remain available when `rtk` is missing; the explicit path and instruction fallback address the exact observed blocker.
- The change cannot prove that Copilot will generate a game or PR until a later authorized remote run.
